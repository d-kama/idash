# AWS Emulator による DuckDB S3 経路の統合テスト

## 概要
AWS Emulator をローカルで動かし、`AssetRepository` の具象 `DuckDbAssetRepository` が S3 上の Parquet を
正しく読み書きできることを確かめる統合テストを追加する。テストは opt-in で、明示的に実行したときだけ走る。

## 背景・目的
- `DuckDbAssetRepository` の S3 経路（`s3://` の location、httpfs / aws 拡張、`credential_chain` 認証）には
  テストがない。既存テストはローカルパスだけを使っており、本番で通る経路が検証されていない。
- DuckDB の httpfs は boto3 を経由しないため、moto のインプロセスモックではこの経路を検証できない。
- あわせて、AWS 公式のローカルエミュレータである AWS Emulator を試用し、本プロジェクトで使い続ける価値があるかを
  見極めたい。

## スコープ
### 対象
- AWS Emulator をローカル（Docker / colima）でビルドし、起動・停止する仕組み
- `DuckDbAssetRepository` を S3（エミュレータ）に向けて動かす統合テスト
- 統合テストを opt-in で実行する専用タスク
- 本番では使わない S3 接続上書き設定の追加

### 対象外
- CI（GitHub Actions）での実行。まずローカルで価値を確かめてから判断する。
- moto の単体テスト（`S3ErrorPageStore` / `common.ssm`）の置き換えや、エミュレータ版との二重化。
  moto で十分に検証でき、重複になるため。
- collect → notify をつなぐハンドラ単位の E2E テスト。今回の主目的（検証できていない経路を埋める）から外れるため。
- CDK スタックをエミュレータへデプロイするテスト。コンテナイメージの Lambda や EventBridge Scheduler への
  エミュレータの対応が不確かなため。

## 要件
### 機能要件
- **R1**: 開発者が 1 コマンドで、エミュレータのビルドから起動、統合テストの実行、停止までを行える。
- **R2**: 統合テストは S3 上の Parquet について次の 3 点を確かめる。
  - PortfolioAsset を save して find すると、負の評価損益を含めて同じ値が返る（round-trip）
  - 一度も save していない location を find すると空を返す
  - 同じ基準日で 2 回 save すると、その日の行が置き換わるだけで重複しない（冪等 upsert）
- **R3**: 通常の `task test` / `task check` / CI では統合テストが実行されず、結果も所要時間も従来と変わらない。
- **R4**: エミュレータの接続情報がない環境で統合テストだけを直接実行すると、失敗ではなく skip になる。
- **R5**: S3 接続上書きを設定しないとき、`DuckDbAssetRepository` の挙動は従来と同じになる。本番の
  `credential_chain` 認証もそのまま使われる。
- **R6**: テスト同士はエミュレータ内の状態を共有せず、実行順や再実行で結果が変わらない。

### 非機能要件
- エミュレータは版を固定する。エミュレータの頻繁な更新で、ある日突然テストが壊れることを避けるため。
- エミュレータは `127.0.0.1` にだけ公開し、外部ネットワークに晒さない。
- 統合テストは実際の AWS を呼ばない。実際の AWS 認証情報が環境にあっても、エミュレータ以外へ届かないようにする。

## 方針
- [ADR-0007](../adr/0007-s3-integration-test-aws-emulator.md): S3 経路の統合テストには AWS Emulator を使い、
  opt-in の層とする。moto の単体テストは残す。
- エミュレータの起動と停止は Taskfile のタスクが担い、pytest は環境変数から接続情報を読むだけにする。pytest から
  Docker を操作すると、失敗時の後始末とログ確認がしにくくなるため。
- 統合テストには pytest のマーカーで印を付け、通常の実行では除外する。
- DuckDB をエミュレータへ向けるため、`DuckDbConfig` に省略可能な S3 接続上書き（エンドポイント、URL スタイル、
  CA 証明書）を追加する。テスト側で接続処理を差し替える案は、検証したい S3 用の認証設定そのものを差し替えて
  しまうため採らない。
- エミュレータは状態をリセットできないため、テストごとにユニークなバケットを使って分離する。
- エミュレータの公式イメージはないので、公式ドキュメントの Dockerfile をリポジトリに置く。
