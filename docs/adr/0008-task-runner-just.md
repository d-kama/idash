# 横断タスクランナーを go-task から just へ移行する

横断タスク（setup / check / synth / deploy / エミュレータ起動など）の定義を go-task（`Taskfile.yml`）から
just（`justfile`）へ移す。版は `mise.toml` で固定する。

go-task の Taskfile は YAML の中に Go テンプレート（`{{.PORT}}`）とシェルが混ざる三重の書式で、`desc` に
コロンを含めるとクォートが要る、複数行の処理を YAML のブロック文字列へ埋め込む、といった YAML 側の都合に
気を遣う場面が多かった。このリポジトリの Taskfile は go-task 固有の機能（`sources` / `generates` による
差分スキップ、`deps` の並列実行）を実質使っておらず、乗り換えで失うものは小さいと判断した。

## Considered Options

- **go-task を使い続ける** — 移行コストはゼロ。ただし上記の書式の扱いにくさは残る。差分スキップや並列依存を
  使う予定もないため、go-task を選ぶ理由が薄い。
- **mise tasks** — 新しいツールを増やさずに済む。ただしツール版管理とタスク定義が同じ仕組みに密結合し、
  mise の版上げがタスク実行の挙動にも波及する。専用ランナーで分けておく方が影響範囲を読みやすい。
- **Make** — どこにでもあるが、ファイル生成を前提にした設計で `.PHONY` の宣言が要り、変数展開や引数の扱いも
  タスクランナーとしては癖が強い。
- **just（採用）** — シェルに近い 1 書式で書け、レシピ引数にデフォルト値を持たせられる（`just bff <parquet>`）。
  shebang / `[script]` レシピで複数行の処理を普通のシェルスクリプトとして書ける。引数なしの `just` で一覧が出る。

## Consequences

- **タスク名を改名した**: just はレシピ名にコロンを使えないため、`setup:ci` → `setup-ci`、`emulator:up` →
  `emulator-up`、`emulator:down` → `emulator-down`、`test:emulator` → `test-emulator` とした。4 個のために
  `mod` で名前空間を切るほどではないと判断した。
- **依存は直列に実行される**: go-task の `deps` は並列だったが、各レシピの依存は 1 個だけなので実害はない。
  `check` は `&&` 以降の依存（本体の後に実行）で「静的検証 → 型生成 → 型チェック → テスト」の順を保つ。
  依存は 1 回の実行内で重複実行されない。
- **ファイル差分による実行スキップは使えない**: 将来 gen-types などを差分ビルドにしたくなったら、自前で書くか
  ランナー選定を見直す。
- **justfile の書き方の注意**:
  - トップレベルのバッククォート変数は、関係ないレシピの実行時にも評価される。環境依存の値（`uname -m` など）は
    レシピ内で計算する。
  - レシピ本体の `#` 行はシェルへ渡されエコーされるため、`set ignore-comments` を設定している。
  - doc コメント（`just --list` に出る説明）はレシピ直前の 1 行だけ。意図の説明はレシピ本体のコメントに書く。
- **版を固定した**: `[script]` 属性など版に依存する機能を使うため、`mise.toml` で `just` の版を固定している。
- 既存の ADR や過去の計画書に出てくる `task xxx` は、当時の記録として書き換えていない。
